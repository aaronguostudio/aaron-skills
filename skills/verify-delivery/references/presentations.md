# Presentations

Read when checking a deck. Use the available presentation authoring/rendering
tools and their specialist instructions. Keep source inspection, rendered layout,
chart correctness and playback compatibility as separate evidence.

## Verify what the deck communicates

Compare the actual deck with its purpose, audience, supplied sources and accepted
style. Check whether the argument supports the intended decision or explanation.
Identify missing essential content, inconsistent state meanings, unsupported
claims and contradictory titles, notes or diagrams. Distinguish a disagreement
with the user's chosen style from a failure to apply that style coherently.

Trace important chart values to the supplied data or calculations. Check units,
periods, labels, denominators, scale and the conclusion drawn from the visual.
A tidy chart with the wrong population is a content failure. Do not invent data
or remove a difficult chart to make the deck look complete.

## Inspect the rendered slides

Render the actual version under review. For a new deck, inspect every slide;
for a revision, inspect changed slides and any affected layout/order. Check
clipping, overlap, font substitution, image cropping, chart labels, contrast and
readability at the intended viewing size. Inspect the content-bearing areas as
well as the title slide. Automated geometry or overflow checks can identify
defects, but passing them does not establish a good visual hierarchy.

After a repair, render the affected material again and inspect it. Moving an
element within the slide bounds does not guarantee the text is readable or that
the fix didn't obscure another object.

## Check the actual delivery formats

If editable source and PDF are required, open/check both and compare them for
missing or changed content. Preserve required editability rather than flattening
slides into images. Inspect notes when another presenter depends on them.
Check promised links, media and animations in a suitable viewer where possible.
A static preview cannot establish animation timing or PowerPoint playback.

Verify file dependencies, access and the presenter's entry point. Report any
unavailable viewer, missing font or untested playback feature with its practical
effect. A successful file parse or export is not a complete deck acceptance test.
