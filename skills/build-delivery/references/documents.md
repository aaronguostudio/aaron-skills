# Documents

Read when building or revising a written deliverable. Use available document
tools and their specialist instructions for editing, rendering and verification.
Keep the requested format and editing method, including tracked changes when
requested. Do not replace a native document with Markdown merely for convenience.

## Write for the reader's next action

Identify what the reader needs to find, understand, decide or execute. Preserve
the source's meaning, the user's chosen structure and the status of decisions.
Separate evidence, interpretation and recommendations. A request for legal review,
for example, does not by itself establish an approval policy.

Choose detail and navigation for the actual reader. An operating procedure needs
usable actions and relevant exceptions; a decision memo needs a clear choice,
reasoning and consequences. Neither automatically needs an executive summary,
table of contents or fixed section template.

Keep names, terms, dates, units and figures consistent. Preserve useful source
pointers and identify missing evidence instead of inventing it. When feedback
changes a rule or term, update dependent examples, tables and instructions too.
Preserve intentional tracked edits and comments rather than silently accepting
them to make the file appear clean.

## Inspect the reading and editing experience

Render in the target format and inspect the whole new document, or changed pages
and affected pagination for a revision. Check tables, page breaks, headings,
lists, footnotes, headers/footers and cross-references. Verify figures and logical
consistency separately from layout. A valid file can still contain a misleading
summary or broken instruction.

Use meaningful heading structure, readable tables and appropriate image
descriptions where relevant. When both source and PDF are requested, inspect the
PDF as well as the editable source. Check links and dependencies from the
receiver's access context; local-only citations can require a portable reference
or an explicitly disclosed access limitation.

Deliver the requested version, with an understandable editing/reading entry
point and any essential supporting files. Report unresolved evidence, decisions
or rendering limits briefly. A prepared file is distinct from a sent, signed or
accepted document.
