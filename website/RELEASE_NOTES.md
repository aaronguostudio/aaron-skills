# Maintaining release notes

The Updates page is a curated, bilingual record of published Aaron Skills releases. Keep the newest entry first and link each version to its actual GitHub release. Dates are the release date in America/Edmonton. Use the published release and tagged source as evidence.

Write for someone using the skills: explain what they can do, what problem a change solves, or a fix that affects their work. Group related improvements and omit routine internal, dependency and testing details. Keep meaningful limitations and availability accurate. Do not present development work, previews or planned changes as released. Backfill selectively rather than inventing highlights for every version; the link to all GitHub releases preserves the complete history. Maintain English and Chinese together.

Add an entry in `src/ReleaseNotes.jsx` as part of an authorized release, then check the page at desktop and mobile sizes in both languages with the website verification command. A website change alone does not publish a skill, and a local or preview build does not establish a production release.
