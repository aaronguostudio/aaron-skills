# Deliver · make the result usable by its receiver

Deliver is a local first-version candidate, invocation ID `deliver-work`. It
prepares stakeholder messages, release notes and usable handoffs, choosing the
channel and media needed by the receiver's next action. Its portable core is
instructions; it supplies no messaging connector, hosting service or deployment
engine and requires no other skill.

## Use

> Use $deliver-work to prepare the message, release notes or handoff this result
> needs. Follow the intended audience and channel, reuse suitable evidence/media,
> preserve the verified availability and make the next action clear.

Start with the [skill](../skills/deliver-work/SKILL.md). It produces actual content,
not only a communication plan. A short text message can be the complete result.
Other tasks may need an email with files, a copyable screenshot page, durable
release notes or an operational handoff. It does not generate every form or
record a video by default.

A promised rerun or regeneration is part of the delivery contract. Include its
required scripts, inputs and sources, then replay the documented command unchanged
from a fresh recipient-only copy with declared dependencies. If that operation
cannot be checked, preserve the limit instead of implying the authoring workspace
travels with the files. Plain messages and reading-only handoffs need no extra
reproduction package.

## Relationship to Share and the rest of the method

Deliver handles audience, purpose, content, channel, applicability, transfer and
the receiver's next action. Existing Share (`paste-ready-update`) retains its
name, invocation ID and runtime ownership for copyable screenshot/update pages.
Deliver may use it as an optional packaging method; a plain message, editable
file or release note does not require Share or the Demo runtime.

Shape can supply the purpose, decisions and useful expression. Build supplies
the actual artifact. Verify or other checks supply evidence and limits. Capture
and Film can supply an authorized demonstration. Deliver carries those facts
into the handoff without upgrading a local/test result into a production or
customer-acceptance claim. See the [task workflow](task-delivery-workflow.md) for
composition across software, documents, reports and reusable templates.

The default output is prepared content when sending/release authority has not
been supplied. Explicitly authorized delivery can use the available tool and
destination, with result verification. Drafting release notes does not authorize
a merge, tag, deployment or announcement. Existing project production policies
and tool instructions remain authoritative.

## Portable local use and evidence limits

Copy the complete `skills/deliver-work` folder into an unused host-supported
skill location, preserving other registrations, and refresh discovery.
`agents/openai.yaml` supplies optional Codex UI metadata. The
[standalone manifest](../bundles/deliver-work.json) includes the skill and its
product/workflow documentation. Deliver is not added to the released Demo
installer or a global skill registration.

Structural validation, reference closure and isolated copying check packaging.
The [authored evaluation cases](deliver-work-evaluation.md) describe future
communication, media, release and receiver trials; they are not completed agent
evaluations. Native host discovery, actual stakeholder comprehension, external
access, connector integration and joint workflow quality require their own
evidence. No public release or website change accompanies this candidate.
